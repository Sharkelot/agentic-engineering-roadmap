# Week 8 — Capstone and technical storytelling

## Objectives
- Assemble a reproducible evaluation narrative from objective, synthetic data, run artifacts, and regression evidence.
- Communicate limitations and safe reuse boundaries honestly.

## Prerequisites
- Weeks 1–7; a completed local run and familiarity with the README.

## Read
- [GitHub README guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes) — communicate purpose, setup, and use.
- [GitHub Actions workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax) — make automated checks reproducible.
- [Week 1](week-01-python-sdk.md), [Week 4](week-04-metrics-regression.md), [Week 7](week-07-deployment-ci.md), [reading map](../references/reading-list.md).

## Build
Create a concise capstone README outline using only the repository's synthetic support cases: objective, setup command, run command, artifact inventory, evaluation criteria, regression command (if compatible baseline artifacts exist), and limitations. Verify instructions by running locally where possible. Include no employer/customer details, private portfolio URL, credentials, or invented results.

## Check your understanding
1. What evidence makes the project reproducible for another learner?
2. How should an absent compatible baseline affect a regression claim?
3. Which limitations belong beside the reported scores?

## Reflection
What claim can your artifacts support today, and what additional evidence would be needed for a stronger claim?

## Done when
- [ ] The README outline names executable local steps and expected artifact files without fabricating outcomes.
- [ ] Limitations and synthetic-only scope are explicit.
- [ ] Attempt the exercise and quiz before opening [answer hints](../solutions/README.md); ask follow-up questions as needed.
